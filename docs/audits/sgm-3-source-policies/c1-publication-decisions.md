# C-1 批次发布审核决策

## 最大目录恢复唤醒

独审指出，全部 priority 变化会清 last_error，随后带有效旧许可的 no-op 也不会执行恢复 UPDATE，因此初版规模用例不足以证明批量恢复成本。

已扩展既有最大目录用例：正式 commit 检查全部 10000 个许可，再设置全部未来 NotReady、传空旧许可，验证恰好 10000 次 SQL 更新、单独小于 10 秒；还原 next_attempt_at 后逐表对照，确保没有顺便改版本、授权或历史。没有增加第二份重型用例，原门槛不变。独立复审关闭。

## 确定性成员绑定与新写入失败

随机授权需要多个条件同时满足，不能依赖 128 cases 必然走到有许可分支来证明成员绑定。已在确定存在的四个许可上固定独立篡改 member revision 与 ID；并补来源观测过期、到期边界及 backend 截止交集的固定用例。

新恢复 UPDATE 也必须进入故障矩阵。新增用例让前组真实改变 priority，后组稳定目标恢复时触发 SQL 错误，逐表及缓存/轮次/epoch 检查全部回滚；移除触发器后同一轮次成功。独立复审关闭两项建议。

首次 worker 回归中两项在夹具 TOML 解析阶段失败，原因是新增夹具遗漏必填 poll_interval_secs。补齐与既有假配置一致的字段后复跑通过，没有修改生产配置校验或业务断言。

clippy 首次指出新测试的 `.err().expect()` 可直接使用 `.expect_err()`，已作等价断言写法清理；复跑只剩既有 6 条警告。未借此清理无关代码。

PolicyRefreshReport 在 catalog 与提交结果一起构造，再由 worker 返回，保证 commit 后没有可失败的目录查询。保留变化 ID 集合供内部结果核对；不增加持久表或另一份调度模型。
