# C2 管理操作审核处置

日期：2026-10-18，基线 da35d8e。范围为内部管理命令及来源模型发现，不包含 HTTP 页面、key 管理或部署。

## 设计审核

- 设置保存与渠道执行分开：三个局部命令使用既有操作表的 Succeeded/0 targets，表示设置已保存；不生成成员目标或许可。架构 I6、SGM-2 回执和 C2 契约同步，后续 UI 必须按 kind 显示，不得显示“渠道已切换”。
- 同值 Pin 沿用原 helper 的 policy_revision no-op；新 OperationId 的组实体 revision 仍增加一次。撤错先正常推进日格，不能笼统承诺跨日仍保留旧周期的 token 耗尽。
- 同步 submit 重放沿原路径更新内存发布屏障，但不改持久版本、error_epoch 或周期历史。发现重放在 GET 之前返回；不为重放重构既有 publisher。
- 冻结四个新 kind 的 wire 拼写。OperationView wire=2，CatalogSnapshot wire=1，数据库版本=7；三个版本各司其职。没有第二套长期操作表。

## 实现审核

- 发现结果中的逗号、NUL、空列表属于上游 InvalidResponse，显式 SyncSourceModels 的同类输入仍为 InvalidInput。统一规范化 helper 不改变旧命令摘要。
- 模型同步提高 source/member 版本后，旧许可必须失效。初次组合测试遗漏后续真实 C1 发布，等待执行不成功是正确行为；测试补原刷新入口并先断言旧许可无效、提前执行不成功，没有放宽执行器。
- PB4 使用真实 B1/O4 和 C1 入口初始化混合来源许可，不以测试专用 publish_route 掩盖新旧版本边界。
- 迁移夹具降级使用生产重建 helper，因此必须在调用前保存独立完整镜像，降级后断言仅 meta 版本变化。PB2 迁移结果直接比较原 v7 镜像；通过原 confirm_member 生成成功操作的非空 confirmed_at/receipt_json，和 unknown 执行、历史、事实一起逐字段比较。
- 有 Content-Length 的超限响应和等待 headers 的超时不能证明流式正文约束。补充无长度、有效 JSON 的 chunked 累计超限，以及先返回 headers 后卡正文的回环响应；12 秒外层守卫防止遗漏正文超时后测试挂住，检查错误不落库且锁/槽释放。

独立审核者对上述修订完成只读复审，静态问题全部关闭。运行结果见 [C2 审核](c2-audit.md)，不以静态复审代替测试。

## 失败记录和范围

首次 catalog 测试编译发现夹具从不可变引用调用可变 snapshot；改为读取已有 SQL 字段，未改生产接口或期望值。首次定向组合测试的 C1 缺步按上文修正，其余失败不被隐藏。

变异筛选中，单独删除 C2 的同组预检查仍被原 save_group_policy_tx 的组归属校验拒绝，行为未变，因此该等价变异不计为“捕获”，也不据此削弱原 helper。保留日志，换成绕过成员接管资格的非等价变异，使用已有未接管成员负例验证。

最终 clippy 指出 v2 DDL 过滤的多重否定和假服务嵌套 if 两处新增风格提示：前者显式命名 included/superseded（`A && !B && !C` 等价于 `A && !(B || C)`），后者合并为保留短路的 &&。独审确认两处等价，复跑定向、机械和 clippy；没有降低断言或改变版本/网络边界。

生产 GLM/火山算法、事实账本、旧 v1–v6 DDL、NewAPI 和执行器冻结。C2 使用原状态事务和执行链；仅模型 GET 有一个全局单飞锁、原64命令槽、10秒总超时、1MiB正文与1000模型界限。未增加按来源的锁表、自动重试、推理探测或周期任务。实际服务保持原版本。
