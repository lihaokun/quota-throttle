# C-1 采集审核决策

## 超界夹具必须到达被测入口

独审静态发现最大目录已含 1000 来源，测试再调用正常 insert_source 会先被既有容量门禁拒绝，无法检验 glm_probe_inputs 的 Storage 路径。改为仅测试 SQL 插入第 1001 条完整、合法来源及 secret/control；没有改生产容量限制或预期错误码。保留整库不变断言，独立复审关闭。

## 取消与等待期变更

取消用例由单源加强为两源两组，第一源完成、第二源等待时取消；检查旧状态/许可/轮次和 input epoch、槽与锁释放及下一轮跳号，直接覆盖部分采集丢弃。

等待期控制/成员变更由固定 80/100ms 延迟改为 QuotaGate 信号量响应闸门：控制变更提交后才释放响应，避免调度负载改变预期先后。闸门使用随机回环端口，只在测试中存在；不是生产代理。独立复审关闭两项建议。

## 完整发送屏障

组合测试仅开启 check_routing 时，空 routing_targets 不会执行“peer 降到目标”的子检查。两次刷新后分别填入独立固定期望目标再执行协调器，保留违规集合为空断言，不从被测目标推导期望。独立复审关闭；原 planner/场景断言不改。

## 全量规模预算失败与最终回读

首次全量为 359 passed、1 failed、1 ignored，404.30 秒；唯一失败为最大目录整轮提交 11051 ms 超出原 10 秒断言，输入组装为 153 ms。这一轮不计验收通过。

未放宽门槛。定位到写后再次完整 load_work 会重复读取和解码本轮未改的来源、组、模型及执行历史。收窄为只对实际变化成员回读 memberships/member_control，仍使用原 decoder 和 member_target；其余字段复用同一 IMMEDIATE 事务输入，不新增跨事务缓存。pending_writes 的依赖仅为执行记录与 channel_id/create_state，本轮均不改。原 Keep/no-op PBT 和非空 unknown 历史测试增加完整 WorkSnapshot 与直接 load_work 的逐字段对照。独审复核所有依赖和跨组 supersede 影响，确认无遗漏或契约偏离。

优化后单用例提交/恢复为 4187/3319 ms；完整目录模块首次复跑为 5343/3779 ms，最终机械检查为 4655/3107 ms。优化后 10 项变异全部捕获，最终全量为 360 passed、0 failed、1 ignored（354.88 秒），门槛在全量负载下也通过。旧失败记录保留，没有用单用例结果替代整体验收。

## 保留的范围

本步不改 DDL、原 GLM 策略或 SourceProbe 算法；read_material 只开放 catalog 内可见性。C2 网络入口只占一个 commands 槽，原手工发布包装限定测试，避免生产二次占槽或外部提交观测。

clippy 指出新属性测试可用 enumerate 替代按索引遍历，已等价清理，不改模型公式或断言。后续功能和生产部署仍按总计划与明确授权推进，不把 C-1 完成解释为整套功能交付。
