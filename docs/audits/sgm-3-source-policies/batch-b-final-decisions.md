# SGM-3 B 组合审核决策

## C1 只读备份的辅助文件计数

首轮新增测试把只读打开备份后留下的 SQLite `-wal/-shm` 当成额外备份，原因是沿用仅匹配文件名前缀的辅助函数。实际备份未被覆盖，生产迁移无需修改。

处置：本组合测试只统计前缀匹配且后缀为 `.sqlite3` 的主备份文件，并排序；数量、原始内容、权限及重试后首次备份字节不变的断言全部保留。独审核实这不是弱化期待。由该夹具错误产生的临时 PBT 种子不作为业务回归提交，确定性矩阵仍覆盖该读备份路径。

## C2 中间 v3 的合法性和实例身份

独审建议：v1/v2 最后一步失败后，除了 schema/版本和原表保真，还应完整验证回填的 core/control/execution，并直接核 v2 实例 ID。

处置：增加三个验证入口，v2 主库和原版本备份均比较实例 ID。增量复审通过；原始表相等断言未删除。

## C3 同一 target 的并行重编译

首轮全量出现 3 个既有预检失败，均在本地进程绑定阶段、管理假服务请求之前；该轮结束为 318 passed、3 failed、1 ignored，不计验收通过。期间同一 target 曾因补强断言而重编译测试程序。

预检以测试进程自身为临时进程，核对 `/proc/<pid>/exe` 与磁盘程序路径；失败现象与运行中替换测试可执行文件一致。单独重跑 8 项预检全部通过，未修改预检生产代码或断言。为排除该干扰，固定最终测试产物后重新跑全量，期间不再在同一 target 编译；变异另用独立源码与 target。最终结果见汇总审核记录。

## 边界

本轮生产代码零修改，SQL 历史收据是测试材料，不是对真实 NewAPI 成功的证明。B 的结论仅涵盖纯策略、内部持久化及迁移/重开；C/SGM-4 的真实终态和原子发布、SGM-7 的生产迁移窗口不因此获准。
