# 状态库与持久操作第二批审核

日期：2026-10-15。基线：7b48182。范围：P8–P10。结论：第二批本地持久化实现已验证；P11–P16 的协调执行与远端确认尚未实现，不能部署新协调模式。

## 独立审核与修正

独立审核先读取契约与操作 schema，再对照本批 diff，不以主 agent 的测试记录代替判断。覆盖迁移只读校验、备份/回滚、身份保留、幂等/代次顺序、跨组隔离、退休、旧收据与测试有效性。

审核发现一个持久收据完整性问题：只按当前 operation_targets 行计数时，已成功操作丢失目标子行后可能仍被显示为较少目标的 succeeded，甚至退化为 0/0。修正后，操作表冻结 expected_targets，成员操作必须恰好一个目标；读取和重开均核对实际集合数量。新增回归分别覆盖成员/来源/组、未成功和已成功记录、丢失一行和全部行，均不能伪装成功。独立复核确认该问题关闭，私有计数有明确完整性用途，不属冗余设计。

R11 的随机迁移主要覆盖 legacy GLM，审核建议补充合法目录形态。已增加混合 GLM/火山、多组、ready/created_disabled/planned/retired、绑定与无渠道成员的确定性迁移回归，比较完整快照、材料与控制初值。独立复核通过。R1 的完整 ACK 状态机仍属第三批，不将本批暂停/恢复和幂等 PBT 称为完整 R1 验收。

| 契约 | 结果 |
| --- | --- |
| 先只读完整验证，再私有备份、单事务迁移 | ✅ 非法旧库不生成备份/不迁移；备份不覆盖旧文件，文件及目录同步 |

## 验证证据

- 全量普通测试：141 通过、0 失败；1 项原生隔离测试默认忽略。第一批已单独验收原生接口，本批未改传输/渠道模块，不声称重新运行了原生验收。
- 新增 21 项测试，含 4 项 PBT，各 128 cases：随机暂停/恢复与重放/重开、跨组完整目标隔离、旧目录完整材料迁移、直接命令 Debug 与回执脱敏。原有 120 项普通测试均保留，未修改原断言。
- 1000 成员完整组操作通过逐 ID priority 检查及 5 秒性能门禁；单项测试本机约 0.51 秒（含 fixture）。
- 迁移故障注入在四个不同 DDL 位置制造同名表冲突，确认元表/版本/旧数据完整回滚、已有备份不覆盖，排除冲突后可以再次备份迁移。
- 操作故障注入分别覆盖操作插入、第二目标插入、第二成员更新，验证源暂停、revision、dirty 和收据同事务回滚。
- `bash scripts/contract_audit/sgm2_batch2.sh` 通过：P8–P10 定位、枚举/SQL/schema 一致、真实 OperationView 与旧 CatalogSnapshot schema、非法样例拒绝、保护文件 diff、目录层零网络执行。
- release 构建通过；Clippy 仅保留 6 个既有风格警告，本批无新增警告。CI 工作流入口仍为 cargo test/build，本轮未推送或触发远端 CI。

首轮两处失败来自测试夹具，未更改生产期望：备份枚举曾将只读打开 WAL 备份后生成的 sidecar 当成新备份，现只统计 .sqlite3 文件；损坏名称测试曾先撞两行同值的 UNIQUE，改为每行不同的非法名称后验证重开拒绝。

定向变异在独立临时源码及 target 中运行；正常 worktree 不修改：
