## 失败记录与修正

1. 首轮 fermat `a1_` 过滤误匹配 1 项旧测试，结果 16 passed / 1 failed；新测试实际 15 / 1。失败发生在火山证据夹具：半开覆盖 end 必须严格大于事件时刻，原夹具将二者都写为 AT。仅修夹具为 end=AT+1，保留非零 token 和失败计数断言；不改生产判据。之后统一用 `s6a1_` 前缀。
2. 下一轮 17 / 1，7.06 秒，真实成员退休之后新 GLM 评估仍显示过期。原因是 consumer 取了退休历史，而原 `group_work` 已排除它。先写并独立批准 [八节 RCA](../../fixes/panel-state-fix-retired-stamp-scope.md)，再给 consumer 加相同过滤；保留原失败断言，并明确历史修改不失效、当前成员退休/移除/新绑定使旧判定失效。
3. 修复后的精确 `s6a1_` 18 passed / 0 failed，7.49 秒，包含 3 组 PBT。日志在 fermat `/tmp/quota-throttle-sgm6-a1.LAtp1k/scope-green.log`。此定向结果不替代全量/变异/性能。
4. 初轮默认 debug 全量 662 passed / 1 failed / 27 ignored，464.22 秒，唯一失败为未改动旧导入容量用例的10秒墙钟断言（catalog/tests.rs:1073）。原源码精确单项随后连续三次通过，完整case 0.74/0.75/0.73秒。先记录并独立批准[计时隔离补齐方案](../../fixes/catalog-fix-import-performance-gate.md)，保留两个原计时窗口、各10秒及全部容量断言；不放宽预算、不降低全量并发。
5. 第二轮默认debug为662/1/28、521.19秒，唯一失败是旧129成员组快照3秒（execution_tests.rs:561）。原副本独立三次通过0.15/0.15/0.14秒。主代理与独立审核系统扫描其余计时，另找到万成员GLM纯容量5秒同类遗漏（未复现失败，原样单项0.04秒通过）；先增补RCA并批准，再等价提取两项。锁/Busy/真实与虚拟超时行为约束保持，生产策略未改。
