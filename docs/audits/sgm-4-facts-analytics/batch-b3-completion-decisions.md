# SGM-4 B3 只读组合及补归属审核处置

日期：2026-10-17。实施基线 `4aa89d6`。本次只覆盖 B3.3–B3.7；[第一步记录](batch-b3-query-decisions.md)保持历史语义。实施/运行证据见[审核记录](batch-b3-completion-audit.md)。

## 只读组合

独审按 workflow §6 先读契约独立提取，再读实现和测试；不把代理的静态检查算作实际运行。

| 反馈或红例 | 处置 |
| --- | --- |
| 阻塞队列中取消早退时，closure 捕获的 target 可能晚于 permit 销毁 | 将 target 显式移到 permit 之后声明的局部值；正常、panic/早退都先清读资源再归还槽 |
| 只有运行中取消，缺队列取消和注册竞态 | 用单阻塞线程的受控队列、预注册取消/128 次同步竞态、实际递归 SQL 中断补齐；等待的是实际工作退出 |
| tuple keyset 与静态下界可能重扫同时间前缀 | 2 万行密集时间夹具实际出现 111218 VM steps 红例；改为同时间 ID 后继和严格后续时间两种 seek，覆盖两表和 Any/Exact/Unknown token，不降门槛 |
| 大规模趋势的 callback 数不是扫描行数，未证明 WAL 保留及释放 | 测试 seam 传实际 scanned；冻结快照期间提交新事实并 PASSIVE checkpoint，读完后 TRUNCATE，核旧 revision/旧用量及 WAL 回收；原始 `/proc` VmHWM 同进程读值反常下降，审计不采纳为可靠峰值，另用外部进程资源计量，均不称查询独占峰值 |
| Tokio 暂停时钟测试后 std/Tokio 绝对时基不一致 | 保留 std 单调 deadline，Tokio timer 使用剩余 Duration；最后仍检查原 deadline，不延长查询预算 |
| 连接只读/关闭顺序需直接证据 | 核 READ_ONLY、query_only、busy_timeout=0 和 SQL 拒写；SQLite xDestroy 测试回调验证 conn 关闭时目录锁尚持有 |

上述静态复审均已关闭。目录锁只将既有 guard 放进 Arc，guard 自身不 Clone，裸 File 副本仍不拥有租约。没有追加数据库身份登记。

## 补归属

首次独审未发现已证实的生产逻辑阻断缺陷；指出三项测试缺口，均在退出前补齐：

| 覆盖缺口 | 处置 |
| --- | --- |
| MAX ID 与深游标页未验证索引成本 | 测试直接取得生产 SQL；2 万事实核 MAX 固定 VM 成本、浅/深 PK seek、结果与无临时排序 |
| 策略隔离断言基于空 permits | 注入非空许可、source_disabled、last_glm_cycle、后端就绪、观测缓存、火山 runtime 与组 preferred/cursor；补正/重放后逐项保持 |
| PB5 的映射/重启时序过窄 | 改为 128 cases 的有界随机事件序列：三路映射分批到达、低/高 ID 迟到、多次重开、页间推进；稳定后有限遍逐事实收敛且原生字段/用量守恒 |

复审确认三项静态缺口关闭，无新增发现。历史映射在现有 A3 入口再次校验的有界开销不另行重构：256 行/10000 映射实际 28 ms，通过 1 秒门禁；保留既有归属算法，不为去掉一次有界校验另造第二套实现。

退出门禁另做独立静态复核：40 入口及 ignored 分类准确、空/全 ignored/漏项被拒；按建议将步骤查找改为 `rg -F`，并明确该脚本不替代独立性能/趋势执行。

## 范围决定

未改变 GLM 策略、火山耗尽规则或协议分组语义；未把扫描结束、消费日志、重试日志条数当可靠请求终态。用户要求连续开发，不再逐小步等待，但不等于允许修改 NewAPI 后端。可靠请求结束事件的最小后端补丁已单独询问，未答复前不实现、不部署，也不削弱“连续 3 个独立请求最终不可用”的契约。
