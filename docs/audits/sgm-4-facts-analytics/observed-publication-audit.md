# 火山观测持久发布审核

日期：2026-10-18，基线 ce23dc7，代码/契约本地提交 `f7e54a2`。范围 O4：应用库 v6 持久观测和 worker 显式发布。本步本地验收通过；整个来源分组功能仍未完成，也没有在线启用。

## 实现边界

同一来源的请求相位、连续失败/成功 token 活动、周期历史和各组目标在同一应用库事务提交。成功活动清零连续计数，但保留已有错误耗尽、token 上限和人工暂停；重复成功不清后续失败，其他来源的成功不串计数。跨撤错/日重置的旧请求以已知最早事件隔离。

B1 fresh 事实和 B3 首次补明来源原子入队；迁移不重播已有历史错误。当前周期 token 复用原分钟联合投影和秒级边缘，没有另一份统计账本。每源最多16条队列/轮；每轮统计1M行、10秒，正向许可还需近期采集、原预检、组就绪、已接管且本源队列消费完。正向许可不是上游账单完整性声明。

GLM/火山只替换本类完整成员 scope，另一类 lease 原样保留；历史退休成员的旧许可会移除。旧 GLM 算法、NewAPI 推理、公开 wire、依赖和 CLI 不变。没有新增后台周期，现行服务未接线或重启。

## 测试和独立审核

新增28项入口：26普通（包含4组各128 cases PBT）和2独立性能。PB1 比较 v5→v6 的完整旧表/实例/备份和重开；PB2 以独立请求相位集合、来源计数和 token 数组验证随机重试/成功/零token/重开；PB3 验证随机 SQL 故障全表回滚和重开后一次应用；PB4 验证混合提供者发布不撤销或延长另一类许可。参考不调用生产归并/选择函数生成预期。

确定性覆盖 F/F/S/F、第三次耗尽后成功清零不解锁、同源跨组、旧请求 cutoff/reset、迟到来源与仅组改善、原生 i64 ID、未来观测、未接管/暂停/组未就绪、不支持类型、序号耗尽、过期/预览/命令忙。故障覆盖入队、相位、队列删除、Runtime、周期历史、组状态/目标/enable_epoch、未知 commit；数据库镜像和 worker 缓存/epoch 同时核验。假 NewAPI 组合实际执行禁用→回读→备用晋升，不只是检查目标表。

首审发现并关闭“忽略 CHECK”与“scope 漏 retired”两项实现偏离；复审建议的第二组定点失败、group-only、密集边缘测试已补。最终独立静态契约审核为0 critical/unresolved，审核者未执行测试。处置与测试夹具失败原因见[处置记录](observed-publication-decisions.md)。

## 五维度检查

- 一致性：正 token 活动清连续计数，原因锁存、cutoff/reset、来源共享和组独立不变；观测不是可靠终态。
- 风格：复用原 catalog 单写事务、Runtime、组选择和 worker 发布 fence，旧 DDL 不修改，原公开 wire 不扩展。
- 正确性：持久相位与队列删除一起提交；来源计量、历史和全部组目标失败全回滚；未知提交闭锁，不发布半轮缓存。
- 性能：来源索引和固定页 keyset、每源16事件、全轮统计/时间预算；新增最大目录与十万消费计时门禁单独执行。
- 可维护性：三表各有真实消费者，没有第二计数镜像或代理；GLM/火山提供者 scope 明确，不复制执行状态机或添加额外后台任务。
